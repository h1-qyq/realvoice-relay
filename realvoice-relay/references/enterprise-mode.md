# 企业反馈汇总模式

## 输入与追溯

为每条原始反馈分配 `feedback_id`，在客户控制的系统中保存原文。进入分析的数据先脱敏；报告中的每个频次、主题和代表性案例都引用一个或多个 `feedback_id`。

## 处理流程

1. 按产品区域、任务场景和问题类型聚类。
2. 合并语义重复项，保留反馈数量和唯一用户数量；两者不得混用。
3. 区分用户亲历、客服标签、系统事实和模型推断。
4. 为主题计算频次、严重度、趋势、情绪强度和置信度。
5. 生成日/周摘要，不把每条原话逐条发送给产品团队。
6. 对外或跨团队分发前抽检代表性样本并完成审批。

## 即时升级

以下类型跳过普通周期汇总，转入对应专用队列：

- 可能造成现实人身危险；
- 活跃安全漏洞或账号接管；
- 未成年人安全；
- 隐私泄露或权利请求；
- 重复扣款、广泛支付故障；
- 大面积服务不可用。

升级不等于公开发送。先进入企业已配置的安全、隐私、账单或事故响应渠道。

## 企业摘要字段

```text
报告周期：
主题：
反馈数 / 唯一用户数：
趋势：
影响程度：
情绪与满意倾向估计：
代表性脱敏案例及 feedback_id：
已核实事实：
待核实内容：
模型推断与置信度：
建议动作、负责人、验收标准：
状态与上次回复：
```

不得删除全部原始反馈后只保留模型摘要；不得让模型估计值进入正式 KPI，除非企业另行建立并验证测量方法。
