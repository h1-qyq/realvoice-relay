# 反馈包与发送稿格式

## 反馈速览

```text
目标平台：
产品区域：
反馈类型：缺陷 / 体验 / 功能建议 / 服务投诉 / 创新想法
使用场景：
发生时间与频率：
影响程度：低 / 中 / 高 / 严重
用户期望：
```

## 情绪与满意倾向

```text
情绪强度：1–5
满意倾向估计：0–10（模型估计，不是调查分）
置信度：低 / 中 / 高
判断依据：只引用原话中可观察的措辞和行为
```

## 事实分层

| 标签 | 含义 | 写法 |
|---|---|---|
| 用户亲历 | 用户声称亲自遇到 | “用户反馈其在……遇到……” |
| 用户转述 | 用户引用他人经历 | “用户转述……” |
| 已核实事实 | 有可访问第一方资料 | 附来源和核验日期 |
| 待核实 | 缺少证据或范围不明 | 使用条件语气 |
| 模型推断 | 分析假设 | 明确写“可能/假设” |

## 建议格式

每项建议包含：

- `horizon`：`now`、`next` 或 `later`；
- `action`：平台应采取的具体动作；
- `user_value`：改善了什么用户结果；
- `platform_value`：减少何种成本/风险或提升何种价值；
- `acceptance`：可以观察和验证的完成标准。

## 邮件模板

```text
主题：【产品反馈】<产品区域>：<一句话问题与期望>

您好，

我是贵平台的真实用户。以下反馈来自我在<场景>中的实际使用经历，希望能帮助团队定位问题并改进产品。

一、发生了什么
<用户亲历，包含必要时间、频率和证据，不扩大范围>

二、造成的影响
<用户影响；如涉及平台价值，明确是分析而非既有事实>

三、建议
1. <近期动作与验收标准>
2. <下一版本动作与验收标准>
3. <长期机制与验收标准>

四、希望获得的回复
请告知该反馈是否已记录、对应反馈/工单编号，以及后续状态可在哪里查看。

<真实性声明>

谢谢您阅读并处理这条反馈。
```
