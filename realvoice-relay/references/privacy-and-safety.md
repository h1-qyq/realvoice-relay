# 隐私、真实性与安全

## 默认脱敏

在草稿、日志和反馈包中默认处理：

- 手机号：替换为 `[手机号已脱敏]`，必要时只留后四位；
- 身份证、护照、驾照：替换为 `[身份信息已脱敏]`；
- 邮箱：替换为 `[邮箱已脱敏]`；
- 银行卡、支付卡、交易凭据：替换为 `[支付信息已脱敏]`；
- 地址、精确位置、未成年人姓名和学校：删除或概括；
- API Key、访问令牌、邮箱密码、钱包私钥、助记词：不得进入正文、日志或反馈包。

若官方安全表单确需身份核验，只提交其明确要求的最少字段，并在发送前确认卡中逐项列出理由。

## 真实性规则

- 将用户原话视为待表达的体验，不自动视为已独立证实。
- 不把“我经常遇到”扩写为“长期普遍存在”。
- 不把单个用户扩写为“很多人”、未经证实的庞大人数或“全体用户”。
- 不虚构订单、截图、日期、金额、损失、法规结论、平台承诺或技术根因。
- 引用公开资料时记录链接和核验日期；引用用户证据时记录脱敏证据 ID。

## 语气转换

保留诉求强度，去除人格攻击和威胁：

| 原始表达 | 发送表达 |
|---|---|
| 带有人身攻击的强硬标题 | “请尽快记录并评估该问题，并告知处理计划” |
| “你们一直敷衍” | “此前回复未能说明具体措施，希望本次提供可追踪状态” |
| “不改就曝光” | “若该入口不适用，请指引至负责团队或正式申诉渠道” |

## 外部写入

邮件发送、表单提交、评论、投票和工单创建都是外部写入。必须在用户看到最终目的地、最终正文、附件和隐私范围后获得明确确认。安装 Skill、完成激活、早先说“全权处理”或仅表达愤怒，都不替代这一步。
