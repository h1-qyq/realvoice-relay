# 官方反馈渠道核验

## 检索顺序

1. 搜索目标平台第一方域名中的“feedback / feature request / 意见反馈 / 帮助与客服 / contact / support”。
2. 打开第一方帮助中心、应用商店开发者页或官方产品文档，确认入口归属。
3. 搜索反馈门户中是否已有相同建议；有重复项时优先投票或补充证据。
4. 记录入口 URL、来源 URL、入口类型、登录要求、是否公开、是否提供回执和页面核验日期。

优先第一方资料。搜索结果摘要、百科、论坛帖子、联系人聚合站和数据经纪页面只能提供线索，不能单独证明目的地属于平台。

## 渠道评分

每项满足记 1 分：

- 第一方页面直接链接或公布；
- 明确接收产品建议/投诉；
- 提供工单号、状态或回复；
- 支持搜索重复项、投票或补充证据；
- 隐私范围与登录身份清楚；
- 最近 12 个月仍可访问或有更新。

优先 5–6 分入口；3–4 分入口可以使用，但在确认卡提示限制；0–2 分不自动提交。

## 类型匹配

| 反馈类型 | 优先渠道 |
|---|---|
| 功能建议、体验问题 | 产品反馈门户、应用内意见反馈 |
| 账号与一般故障 | 官方客服工单 |
| 付款、退款、账单 | 官方账单争议渠道 |
| 个人信息访问/删除 | 官方隐私请求渠道 |
| 安全漏洞 | 官方安全响应或漏洞赏金入口 |
| 违法或危险内容 | 平台举报与紧急升级入口 |

不要把安全漏洞发到公开建议板，不要把普通功能建议发给新闻、投资者关系或安全邮箱。

## 失败处理

找不到可验证入口时：

1. 明确写“未找到可验证的官方反馈目的地”；
2. 给出已核实的官方帮助中心首页；
3. 保留完整草稿；
4. 停止发送，等待用户在官方应用中补充入口。
