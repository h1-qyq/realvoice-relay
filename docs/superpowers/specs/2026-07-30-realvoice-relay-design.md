# RealVoice Relay（真声直达）设计说明

## 目标

创建一个可安装的 Agent Skill，把用户零散、愤怒或不完整的产品反馈转化为真实、克制、可执行的改进信号，并送达经核实的官方反馈入口。Skill 同时支持个人反馈和企业批量收集场景，以“一次 0.01 美元等值 USDC 激活”为商业入口。

## 命名与定位

- 机器名：`realvoice-relay`
- 展示名：`RealVoice Relay · 真声直达`
- 核心承诺：让真实用户声音抵达真正能改进产品的人。
- 明确边界：它不是“产品经理”，也不冒充用户、平台员工、监管机构或群体代表。

## 方案比较

### 方案 A：纯提示词 Skill

只提供整理流程和邮件模板。优点是安装简单；缺点是无法可靠核验渠道、约束发送行为或实现付费激活。

### 方案 B：Skill + 可验证脚本 + 独立激活网关（采用）

Skill 负责判断与表达，标准库脚本负责反馈包和激活回执校验，独立 x402 网关负责一次付费激活。它既能离线安装，又为后续商业化保留清晰接口。

### 方案 C：完整 SaaS 平台

建设账号、数据库、企业仪表盘、队列和计费后台。长期价值高，但超出一个 Skill 仓库的合理首版范围，也需要运营主体、域名、钱包和隐私政策。

## 用户流程

1. 首次运行时检查本地激活回执。
2. 未激活时请求配置的激活端点；端点通过 x402 声明 0.01 美元 USDC 价格。Agent 钱包签名并付款后获得永久回执。
3. 询问用户的 Agent 发件邮箱。若没有，给出 AgentMail 官方注册链接和三步说明；不索取 API Key、助记词或邮箱密码。
4. 接收用户原始反馈，提取目标平台、使用场景、发生时间、期望结果、影响和证据。信息不足时只补问会改变结论的关键问题。
5. 仅从第一方页面核实反馈入口，并按“可跟踪产品反馈门户、应用内反馈、工单、官方支持邮箱、官方社区入口”排序。
6. 输出结构化反馈简报和可发送正文，区分用户陈述、已核实事实和模型推断。
7. 显示最终目的地、正文、附件和隐私处理结果，请用户进行发送前确认。
8. 通过已连接的 Agent 邮箱或官方表单提交；保存渠道、时间、主题和回执，不保存邮箱密码或钱包私钥。

## 反馈内容契约

每份反馈包含：

- 反馈速览：平台、产品区域、类型、场景、频率、影响程度。
- 情绪与满意倾向：情绪强度 1–5、满意倾向 0–10、置信度；明确标注为模型估计。
- 事实分层：用户亲历、用户转述、已核实事实、待核实内容、模型推断。
- 核心问题与价值影响。
- 可执行建议：近期修补、下一版本、长期机制；每项给出验收标准。
- 脱敏后的真实原话片段。
- 希望平台采取的行动和回复方式。
- 真实性声明：内容源于真实用户自愿提供的体验，经 Skill 整理，推断与建议不冒充事实。

## 渠道核验

- 至少有一个第一方来源证明入口属于目标平台。
- 优先选择能生成工单、显示状态、允许投票或承诺回复的入口。
- 搜索已有建议，存在重复项时优先投票或补充证据。
- 不猜测邮箱，不从数据经纪、聚合目录或搜索摘要直接提取联系方式。
- 安全漏洞、违法内容、账单争议、隐私权请求分别走对应官方专用渠道，不混入普通产品建议。
- 找不到可验证入口时只交付草稿和官方帮助中心导航，不发送。

## 真实性、语气与隐私

- 去除辱骂、威胁、夸大和未经证实的群体数量，但保留问题的紧迫度。
- 不虚构影响人数、持续时间、订单、损失、平台承诺或技术原因。
- 完整身份证号、手机号、住址、支付信息、未成年人信息和认证凭据默认脱敏。
- 只在官方安全渠道确有必要时提交最少身份信息。
- 满意度只能称为“满意倾向估计”，不能冒充调查分数。
- 任何外部发送、表单提交或评论发布都需要看到最终内容后的明确确认。

## 企业模式

企业接入时按批次聚类、去重和排序，不逐条轰炸产品团队。原始反馈在客户控制的系统中留存，以不可逆脱敏摘要和反馈 ID 进入报告。高风险安全、隐私、账单和大面积故障即时升级；其余生成日/周汇总。每条结论必须能回溯到一个或多个反馈 ID。

## 付费激活

- 标准价格：一次性 `USDC $0.01`。
- `¥0.06` 仅作为大致展示值，实际汇率可能变化；首版不接法币扣款。
- 激活网关使用 x402 `exact` 方案。卖方只配置收款地址和激活签名密钥，不接触买方私钥。
- 成功支付后签发与 `agent_id` 绑定的 HMAC 回执；后续本地校验回执，不重复扣费。
- 重复请求使用同一 `agent_id` 时，服务端应返回既有激活状态或通过幂等键避免重复付款。
- 仓库不得内置收款地址、私钥、API Key 或生产密钥。

## Agent 邮箱

默认推荐 AgentMail，因为其提供 Agent 专用邮箱、API、Webhook 和 MCP。首次使用只要求：

1. 打开 `https://agentmail.to` 注册，或让 Agent 调用官方 sign-up 接口。
2. 创建一个独立收件箱，例如 `feedback-agent@agentmail.to`。
3. 将 AgentMail MCP `https://mcp.agentmail.to/mcp` 连接到 Agent。

Skill 不要求用户把 API Key 粘贴到对话中；密钥应保存在运行时的安全配置中。

## 组件

- `realvoice-relay/SKILL.md`：核心判断流程和输出契约。
- `realvoice-relay/references/`：渠道核验、写作结构、企业模式、邮箱与激活说明。
- `realvoice-relay/scripts/build_feedback_packet.py`：把结构化输入规范化为可审计反馈包。
- `realvoice-relay/scripts/check_activation.py`：校验本地激活回执或调用验证端点。
- `activation-gateway/`：x402 一次付费激活示例和永久回执签发逻辑。
- `tests/`：Skill 合同、脚本和网关回执测试。

## 错误处理

- 渠道来源不明确：停止在草稿阶段。
- 发件邮箱未配置：只提供正文和极简设置步骤。
- 激活端点不可达：不扣费，显示可重试原因；不把网络失败当作未付款。
- 回执损坏或绑定到其他 Agent：拒绝激活并提示重新验证。
- 用户要求猜邮箱、伪造证据或代替群体发言：拒绝该部分，继续提供真实、可核实的版本。
- 发送工具返回未知状态：不自动重发，先查询已发送邮件或工单，避免重复提交。

## 验收标准

- Skill 元数据通过官方 `quick_validate.py`。
- 自动化测试覆盖渠道核验、隐私、真实性、满意倾向标注、发送确认、0.01 美元价格和永久回执。
- 三个压力场景前向测试中，Agent 不猜渠道、不泄露敏感信息、不伪造群体事实、不跳过发送确认。
- 激活网关在未配置钱包或密钥时安全失败；回执可签发、校验、拒绝篡改和拒绝错误 Agent。
- 仓库无密钥、无占位 TODO、无旧名称残留。
